  • Dropdown requires custom overlay/modal on mobile
  • Two click-targets for category (parent chip + dropdown) may confuse
  • Users browsing non-food may not notice the dropdown exists

  • Best compromise within the current top-bar layout model
  • Desktop + mobile without a major layout change

Option C — Desktop sidebar model
Challenge the chip-heavy header by moving all navigation to a permanent left sidebar. The main content area is freed for filters-as-inputs (checkboxes, tree), and the card feed gets maximum vertical space. Mobile would collapse the sidebar into a bottom sheet or drawer.
✓ Pros
  • Maximum card feed height — feed starts at top on desktop
  • Hierarchical category tree is self-explanatory, no chip clutter
  • Tag filters can expand without fighting header space
  • Familiar pattern from e-commerce (Zalando, Amazon, REWE shop)
✗ Cons
  • Desktop-only — requires a separate mobile layout (drawer/sheet)
  • Significant layout rewrite; highest implementation effort
  • Makes SparTrack feel more like a product catalogue than a deal ticker
  • Sidebar steals 220px of horizontal card space
★ Best for
  • Desktop power users who browse by subcategory
  • A future "full catalogue" mode if aldi-produkte is added
  • Sessions where the user has a shopping list and filters heavily
Key risk: Makes SparTrack feel like a traditional webshop rather than a weekly-deals aggregator. The "browse current promotions" use case doesn't need heavy filtering — the sidebar may solve the wrong problem and slow casual browsing.

✓ Pros

  • Bottom sheet is native mobile UX, users know how to use it
  • Compact row works without a major header redesign
  • Deal browsing remains the hero action

  • Category not discoverable without opening the sheet
  • Requires sheet component + gesture handling (new code)
  • Desktop experience may feel too compact or under-utilised
  • Two menus side by side (Stores ▾ and Filters ▾) may feel redundant
★ Best for
  • Mobile-majority audience
  • Users who browse quickly then filter only when needed
  • Progressive enhancement over current layout

Design notes

• Cards visible without scrolling on any modern phone.

• Browse row (All / Grocery / Haushalt & Freizeit) stays visible at all times — parent switch doesn't need the sheet.

• Sheet opens on: tapping a subcategory chip area, or the "Filter" button in compact row.

• "Übernehmen" applies the selection and closes sheet.

• On desktop the sheet becomes a sidebar or inline expanded row.

Option E — Search-first model
Bet on search as the primary navigation mechanism. The hero is a large, prominent search input with contextual suggestion chips below it. Category and store filters are secondary — compact and out of the way — because users who know what they want search for it.
✓ Pros
  • Dramatically reduces visible taxonomy complexity
  • Works well for intent-driven users ("where is Persil cheapest?")
  • Search with fuzzy matching already exists in SparTrack
  • Clean, modern aesthetic — cards start higher
✗ Cons
  • Browsing users ("show me this week's dairy deals") lose discoverability
  • Suggestion chips require curation and may not surface the right categories
  • Zero-results risk if search can't handle misspellings or German compound words
  • Doesn't solve the category UX problem — just hides it
★ Best for
  • Intent-driven users with a specific product in mind
  • Power users who already know SparTrack's offer landscape
  • Future "deal alert" or "saved search" feature integration
Key risk: SparTrack's primary use case is browsing this week's deals, not finding a specific product. Relegating category browsing to secondary status may frustrate the majority of sessions where the user is in "show me what's good" mode, not "find X" mode.

Option F — Header-integrated search + story-style store row
Pull the search bar out of the page body and embed it directly in the sticky app bar, next to the SparTrack logo. Below the header, replace text store chips with circular "story ring" store bubbles — brand-coloured rings, tap to select. A two-tab category bar (icon + label) replaces the three-chip parent row. Result: cards start at viewport line 3.
✓ Pros
  • Search is always reachable — one tap anywhere in the header
  • Story rings are visually distinctive and instantly store-identifiable by color
  • Saves the most vertical space of any option that still shows stores
  • Header stays useful when scrolled — search never disappears
✗ Cons
  • Search bar in header is narrow on mobile — typing feels cramped
  • Story rings are an unfamiliar pattern for a deal app (Instagram association)
  • Brand colors must be implemented and maintained per store
  • Store name labels below each ring add height back
★ Best for
  • Users who switch between stores frequently
  • Sessions that start with a search (product-intent first)
  • A visual refresh that signals "new SparTrack" without rebuilding routing
Key risk: The search bar shrinks to fit alongside the logo — on mobile it may feel too tight. Consider expanding it to full-width on focus (slide logo to icon) or accepting that mobile search lives in its own overlay.

Option H — Ultra-compact: full search in header + single action strip
Absolute minimum chrome above the card feed. The header carries the logo and a wide search bar. Immediately below: one single horizontally-scrollable strip of pill buttons covering every filter axis — stores, status, category, quick tags, sort. Nothing else. Cards start at line 2 of the viewport. Popovers fly out from each strip pill on tap.
✓ Pros
  • Highest card density — feed starts after just two elements (header + strip)
  • Single persistent strip is fully self-contained — every filter is reachable from one place
  • Strip scrolls horizontally; no overflow or wrapping issues
  • Clean, bold, very "app-like" feel
✗ Cons
  • Users must tap to discover what's inside each pill — hidden by default
  • Active filter state is hard to communicate in a single strip pill label
  • Popover implementation adds new component code
  • Subcategory selection requires two taps (Category ▾ → tap subcategory)
★ Best for
  • Power users who filter frequently and have learned the UI
  • Mobile-first: maximum screen space, minimum chrome
  • A "v2 design language" milestone for a future major version
Key risk: First-time users may not know any filters exist. The strip must signal interactivity clearly (chevrons, hover states, a non-default active color) — otherwise it reads as decorative. Consider a subtle "hint pulse" on first load to draw attention to the strip.

Option I — Editorial rows (Netflix/Spotify-style curated sections)
No filter bar at all on initial load. The page is organized as labelled horizontal-scroll sections — "Top Deals", store spotlights, category rows. Each row has a title + "Alle anzeigen →" link. The header carries the logo and search. Filtering is implicit: tap a section title to enter a filtered view. This turns SparTrack into a curated editorial feed rather than a filter tool.
✓ Pros
  • Zero filter chrome — cards start on line 1; the experience is entirely content-first
  • Editorial sections = curated intent: Top Deals, Store Spotlight, Bio picks
  • Natural infinite scroll down; horizontal scroll per row for variety
  • "Alle anzeigen →" is an implicit "filter by this section" — no explicit filter UI needed
  • Familiarity from Netflix, Spotify, App Store — users already know this pattern
✗ Cons
  • Users who want "all Lidl dairy deals" must know to tap the section title (unclear)
  • Section curation requires backend logic to populate rows (more API complexity)
  • No obvious place for advanced filters (tag: Halal, subcategory: frozen)
  • Large layout change — most divergent option from current SparTrack
★ Best for
  • Discovery-mode browsing — "what's good this week?"
  • Mobile sessions where users have no specific product in mind
  • SparTrack v2 / future redesign milestone, not a quick fix
Key risk: This is the most disruptive option — it changes the browsing metaphor from "filter + grid" to "curated rows." The current search, wishlist, and compare features need rethinking. Best evaluated as a long-term vision, not a short-term fix.

  • Long page when many categories exist
  • No cross-category filter (e.g. "all Bio across sections")
  • Store selector needs a separate mechanism
★ Best for
  • Casual weekly browsers with no specific product in mind

Wishlist in particular is the highest-engagement utility tab — losing it from sight is a retention risk. Three placement strategies are mocked side-by-side below for both mobile and desktop.
✓ Decision criteria
  • Wishlist needs an unread/match badge — promote to icon
  • Compare is task-driven — fine in overflow
  • Recipe / Prospekte / Lab are low-frequency — overflow / "More"
  • Deals is the home — implicit when no other tab is selected
✗ What to watch for
  • If Wishlist drops below ~10% of session entries after the change, the placement failed
  • Mobile bottom-nav must keep ≥3 primary tabs visible without truncation
  • "More" overflow should never hide >3 tabs (becomes invisible)
★ Recommendation
  • T2 on desktop — Wishlist + Compare as header icons with badges
  • T2 on mobile — bottom nav keeps Deals / Wishlist / Compare + More
  • Pair with Option N or R; Option T is the tab-routing layer, not a filter layout
Why it matters: SparTrack's onboarding tour explicitly highlights Wishlist as the value-loop. Hiding it behind "More" while promoting search is a measurable funnel risk. Decision should be data-backed (current Wishlist click-through from Deals tab is ~22%, per CLAUDE.md context).

  • 1
    Should subcategories be permanently visible or hidden behind a category picker?
    Permanent (Option A) maximises discoverability but consumes ~40px of vertical space that could show one more card row on mobile. Hidden (Options B, D) bets that users either know what they want or are satisfied with the parent-level split (Grocery / Haushalt & Freizeit).

    Signals to check: How often do users select a subcategory chip vs leaving it at "All Grocery"? If subcategory usage is <15% of sessions, hiding it behind one click is probably fine.

    Decision: _______________
  • 2
    Should Bio and Vegan remain visible as quick toggles in the main control area?
    Bio and Vegan are cross-cutting — they apply across all categories and stores. Keeping them as chip-level shortcuts (Options A, B, E) respects that they're used orthogonally to category. Hiding them in a filter drawer (Options C, D) treats them like niche filters, which may under-serve the health-conscious segment.

    Counter-argument: Frozen, Gluten-free, Halal, and Pets could make equally strong claims for a quick chip. If Bio + Vegan get shortcuts, where does the list stop?

    Decision: _______________
  • 3
    Should "Pets" be a visible filter, a subcategory pill, or both?
    Pets (Tierbedarf) is currently a tag and a non-food subcategory. It's structurally part of "Haushalt & Freizeit" in the taxonomy, but pet food is purchased as routinely as dairy — so it arguably deserves a fast shortcut. Options to consider:
    • Subcategory pill within Haushalt & Freizeit (current plan)
    • Quick-access chip at the top level alongside Bio / Vegan
    • Both — a parent-level chip that pre-selects Haushalt & Freizeit + Tierbedarf
    • Search suggestion chip ("🐾 Tiernahrung") in Option E model

    Decision: _______________
  • 4
    Should cleaning and laundry items be under Haushalt, Drogerie, or their own group?
    Persil, Ariel, Fairy etc. are currently classified as non_food / household (Haushalt). German retail typically puts them in "Drogerie & Reinigung" or a standalone "Haushalt" aisle. Practical impact: if Drogerie and Haushalt are both subcategories of Haushalt & Freizeit, users who search "cleaning" need to know which subcategory to use.

    Options: (a) keep them merged under Haushalt, (b) split "Reinigung" as its own pill, (c) ignore subcategory and rely on search.

    Decision: _______________
  • 5
    Is "Haushalt & Freizeit" the right German label for non_food?
    Tested candidates:
    • Haushalt & Freizeit — broad, familiar from DM/Rossmann store layout. Covers electronics, garden, clothing, baby.
    • Non-Food — precise but feels technical/English. Retail insiders use it; consumers may not.
    • Home & More — catchy but vague. "More" is not helpful for navigation.
    • Drogerie & Mehr — names the dominant category (Drogerie) but undersells electronics/garden.
    • Nicht-Lebensmittel — German but awkward; negative definition.

    Recommendation: "Haushalt & Freizeit" is the strongest choice. It mirrors how DM, Rossmann, and Kaufland label this floor section and maps to how German shoppers mentally group non-food purchases.

    Decision: _______________
  • 6
    Should desktop and mobile use different filter layouts?
    Most modern deal aggregators (Idealo, Preisvergleich, Amazon) use responsive layouts: sidebar on desktop, drawer/sheet on mobile. SparTrack currently uses a single layout for both.

    If you select Option D (mobile-first), a responsive desktop companion is needed. If you select Option C (desktop sidebar), the mobile story is incomplete. Options A and B work on both form factors without branching.

    Engineering cost: A responsive split (sidebar desktop, sheet mobile) adds ~1–2 days of CSS work but produces the best experience per device. A single unified layout (A or B) is shippable in hours.
